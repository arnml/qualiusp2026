## Null case

1. **Training data provenance is not locked.** The notebook checks hashes for the evaluation files, but only prints abbreviated hashes for the training files; a changed or corrupted training file would not stop the run ([make_notebook.py:27–36](experiments/exp16_rank2_replication/make_notebook.py:27)). Add fixed SHA-256 assertions for all three training parquet files before training.

2. **The HotpotQA exclusion is a claim, not a checked invariant.** The protocol says the 1,300 evaluation IDs exclude IDs used in exp01–exp07, but the notebook and `data.load` do not verify that exclusion ([PROTOCOL.md:16](experiments/exp16_rank2_replication/PROTOCOL.md:16), [data.py:55–63](experiments/exp16_rank2_replication/data.py:55)). Add an assertion against the historical ID lists before training or evaluation. The supplied `split_ids.json` has disjoint tune/test sets of 300/1,000 IDs per dataset, but that alone does not establish the historical exclusion ([split_ids.json:1](experiments/exp16_rank2_replication/split_ids.json:1)).

3. **The pair match is real but narrower than “identical training.”** The control assertion checks equal labels, paragraphs, and pair order, not queries ([train.py:31–41, 55–57](experiments/exp16_rank2_replication/train.py:31)). Different query lengths change truncation and padded batch shapes; with dropout, the same seed does not ensure equivalent stochastic training noise. Report per-pair encoded lengths and truncation rates by mode, and add a seed-matched control-vs-control delta to show whether a rank-2 graft can recover ordinary run variation.

4. **Truncation may discard conditioning context.** Both training and inference use `truncation="only_first"` except when a paragraph alone exceeds the limit ([data.py:71–75](experiments/exp16_rank2_replication/data.py:71)). Because the query puts the question first and selected paragraphs afterward, long queries can lose their later context; the “most recent first” ordering means older selected paragraphs are especially likely to be dropped ([data.py:66–68](experiments/exp16_rank2_replication/data.py:66)). Record token-length/truncation rates by step and dataset; report a cheap untruncated-to-limit sensitivity subset or explicitly scope the claim to the retained context.

5. **The training/evaluation hardware is not enforced as specified.** Training and evaluation accept any CUDA device; the notebook only prints the GPU name ([train.py:27, 51](experiments/exp16_rank2_replication/train.py:27), [evaluate.py:25, 88](experiments/exp16_rank2_replication/evaluate.py:25), [make_notebook.py:39–40](experiments/exp16_rank2_replication/make_notebook.py:39)). Assert T4 in the notebook and save the GPU name, library versions, and determinism settings in run metadata. This matters because only one seed is preregistered.

6. **The primary metric is easier and has a different ceiling from exp12.** Exp16 counts full support within `|gold|+1` among only 10 paragraphs; exp12’s cited result is recall@5 on MuSiQue ([PROTOCOL.md:33–35](experiments/exp16_rank2_replication/PROTOCOL.md:33), [exp12 README:19](experiments/exp12_matched_control/README.md:19)). A positive replication would support transfer of the graft result under this new metric, not equivalence to the original effect size. Add a preregistered fixed-k sensitivity using the same k across datasets, and show results by support count/type.

7. **The recovery ratio is unstable when the denominator is small.** The gate is a *tuning-set point estimate* of a 0.05 gap, while the test ratio divides by the test-set gap ([PROTOCOL.md:48–52](experiments/exp16_rank2_replication/PROTOCOL.md:48), [analyze.py:42–45, 65–72](experiments/exp16_rank2_replication/analyze.py:42)). The bootstrap maps every nonpositive resampled denominator to recovery 0, which does not represent an ordinary ratio interval. Require a positive test gap with a confidence bound, and use a ratio method that handles a near-zero denominator (e.g. Fieller), or make the primary test a paired difference in graft vs. full-model hits.

8. **The bootstrap interval is not a decision rule with a stated error rate.** A percentile CI over 5,000 paired question resamples is used as a threshold test, with no calibration or power justification; denominator instability can make its behavior hard to interpret ([PROTOCOL.md:51–53](experiments/exp16_rank2_replication/PROTOCOL.md:51), [analyze.py:67–72](experiments/exp16_rank2_replication/analyze.py:67)). Pre-register a minimum detectable effect / power calculation and define how an inconclusive interval is classified.

9. **Multiplicity depends on the wording of the conclusion.** Requiring both datasets to hold is a conjunctive claim, for which no correction is needed to claim “both”; saying “partial” when either one holds is a disjunctive claim and inflates false positives without correction ([PROTOCOL.md:53–63](experiments/exp16_rank2_replication/PROTOCOL.md:53)). Either label one-dataset success exploratory or adjust the partial-claim rule.

10. **The random graft does not rule out training-run noise.** It is compared with the real rank-2 graft only on tuning data, while both models come from one seed ([PROTOCOL.md:41, 49](experiments/exp16_rank2_replication/PROTOCOL.md:41)). A positive result could reflect a seed-specific parameter difference whose leading directions happen to help. Add a cheap seed-matched null delta if compute permits; otherwise narrow the conclusion to “the rank-2 component of this single fitted delta transfers on the held-out questions.”

11. **Other positive-result alternatives:** HotpotQA A1 was fine-tuned on the full HotpotQA training split, including the source of exp16’s training sample ([PROTOCOL.md:20](experiments/exp16_rank2_replication/PROTOCOL.md:20)); this can make the experiment benchmark-specific even if the pair comparison is fair. Report the result as adaptation of A1, and add a run from a checkpoint without HotpotQA fine-tuning before claiming dataset-general transfer.

12. **Concrete pre-run priorities:** (1) hard-check all training-file hashes and Hotpot historical-ID exclusions; (2) log token lengths/truncation by step and mode; (3) preregister a denominator-stable recovery rule, power rationale, and treatment of the “partial” claim; (4) enforce/log T4 and software versions; (5) add a seed-noise null or qualify the single-seed claim.
