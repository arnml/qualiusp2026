## Adversarial pre-run review

I found no obvious overlap among the four train-derived splits: each has the stated size and unique IDs, and their pairwise intersections are empty (`split_ids.json`, single-line JSON). That does not establish that the source rows or model artifacts match the registered versions.

### Threats to a positive result

- **The “matched” comparison changes both model and inference mode.** The primary compares M1-iter used iteratively with M1-ctrl used one-shot ([PROTOCOL.md:14–19](</C:/code/qualiusp2026/experiments/exp14_benefit_router/PROTOCOL.md:14>)). Exp13 says the models used identical pairs ([README.md:4](</C:/code/qualiusp2026/experiments/exp13_cascade/README.md:4>)), but this does not isolate the benefit of iterative inference from the benefit of the iterative training objective. `rank.py` already defines `iter_oneshot` and `ctrl_iter` ([rank.py:27–30](</C:/code/qualiusp2026/experiments/exp14_benefit_router/rank.py:27>)); the notebook runs only `ctrl_oneshot` and `iter_iter` ([make_notebook.py:57–59](</C:/code/qualiusp2026/experiments/exp14_benefit_router/make_notebook.py:57>)). **Before running:** score those two extra configs on `b_eval` and report the 2×2; otherwise attribute the effect to the *model-plus-inference package*, not iteration alone.
- **Model identity is not enforced in the notebook.** It prints two model hash prefixes but does not assert expected hashes ([make_notebook.py:48–50](</C:/code/qualiusp2026/experiments/exp14_benefit_router/make_notebook.py:48>)); `rank.py` records whichever `model.safetensors` is present ([rank.py:69–81](</C:/code/qualiusp2026/experiments/exp14_benefit_router/rank.py:69>)). **Before running:** assert full expected hashes for both model files, and record tokenizer, Transformers, PyTorch, CUDA, and GPU versions.
- **Stale ranking files can be silently reused.** The notebook reuses exp13 router/dev rankings if destination files already exist ([make_notebook.py:54–56](</C:/code/qualiusp2026/experiments/exp14_benefit_router/make_notebook.py:54>)); `rank.py` skips a config with a matching model hash without checking its IDs ([rank.py:66–73](</C:/code/qualiusp2026/experiments/exp14_benefit_router/rank.py:66>)). The analysis checks IDs for the four analyzed splits, but the reused rankings are only indirectly protected ([analyze.py:27–36](</C:/code/qualiusp2026/experiments/exp14_benefit_router/analyze.py:27>)). **Before running:** require an empty output directory, or validate every reused file’s split ID list, model hash, tokenizer hash, and row count before accepting it.
- **Truncation is not audited.** Iterative queries grow with selected paragraphs; `encode` truncates the query to 512 tokens and falls back to `longest_first` if a paragraph alone is too long ([data.py:86–91](</C:/code/qualiusp2026/experiments/exp14_benefit_router/data.py:86>)). Exp13 reports the oldest selected paragraph is truncated at the last step for 17–19% of 4-hop questions ([README.md:42–43](</C:/code/qualiusp2026/experiments/exp13_cascade/README.md:42>)). `rank.py` logs an untruncated query length, but the analysis never uses it ([rank.py:44–54](</C:/code/qualiusp2026/experiments/exp14_benefit_router/rank.py:44>)). **Before running:** log effective encoded lengths/truncation per step and report primary results on truncated vs untruncated cases.
- **“Passes” may not match compute.** The ≤50 cap counts candidate scores, not tokens processed or wall time ([analyze.py:69–73](</C:/code/qualiusp2026/experiments/exp14_benefit_router/analyze.py:69>)); query lengths differ by step. **Before running:** report total input tokens and GPU seconds alongside passes.
- **Score features may partly encode length/truncation.** The router uses the one-shot top-10 scores and entropy ([analyze.py:54–62](</C:/code/qualiusp2026/experiments/exp14_benefit_router/analyze.py:54>)); that is allowed, but may proxy question or candidate-set artifacts rather than benefit. Cheap check: compare against a text-only router and report performance by hop count and truncation status.

### Decision-rule problems

- **Power is weak by the protocol’s own estimate:** roughly 50% for the assumed +0.015 effect ([PROTOCOL.md:46–49](</C:/code/qualiusp2026/experiments/exp14_benefit_router/PROTOCOL.md:46>)). A nonsignificant result would not establish no useful routing signal. The gate also makes “not testable” a possible outcome based on the same `b_eval` used for the primary ([analyze.py:117–123](</C:/code/qualiusp2026/experiments/exp14_benefit_router/analyze.py:117>)); report gate, effect, and CI regardless, and do not interpret a failed gate as evidence that benefit is unlearnable.
- **Threshold selection is noisy and coarse.** It selects the best cascade recall among up to 101 tune-set quantiles ([analyze.py:86–95](</C:/code/qualiusp2026/experiments/exp14_benefit_router/analyze.py:86>)). The independent eval prevents direct threshold leakage into the primary, but tune recall is optimistically selected and threshold stability is unknown. Cheap check: bootstrap `b_tune` to show the distribution of τ and routed fraction; keep eval untouched.
- **The CI is not the decision rule.** Primary success uses McNemar p<.05 and direction, but the stated worthwhile effect is +0.01 ([PROTOCOL.md:46–49](</C:/code/qualiusp2026/experiments/exp14_benefit_router/PROTOCOL.md:46>), [analyze.py:119–123](</C:/code/qualiusp2026/experiments/exp14_benefit_router/analyze.py:119>)). A tiny positive can pass. Add a requirement that the effect estimate or lower CI bound meets the predeclared worthwhile-effect criterion, and report the paired CI.
- **Secondary claims have no multiplicity adjustment.** “Beats hop router” and non-inferiority are both tested, plus multiple descriptive `k` and hop strata ([PROTOCOL.md:50–59](</C:/code/qualiusp2026/experiments/exp14_benefit_router/PROTOCOL.md:50>), [analyze.py:124–129](</C:/code/qualiusp2026/experiments/exp14_benefit_router/analyze.py:124>)). Keep them explicitly exploratory or predeclare a correction; do not treat either as confirmatory.
- **Non-inferiority uses a two-sided percentile bootstrap CI** and a tight −0.01 margin ([analyze.py:49–51](</C:/code/qualiusp2026/experiments/exp14_benefit_router/analyze.py:49>), [analyze.py:125–129](</C:/code/qualiusp2026/experiments/exp14_benefit_router/analyze.py:125>)). Predeclare a one-sided 95% paired CI method and justify the margin. The protocol does not define a recovery ratio or `r*`; if either will be reported, define its formula, CI, and selection rule before seeing eval.
- **Metric and input integrity deserve explicit checks.** `ranks()` checks IDs and permutations but not lengths of `orders`, `passes`, or `top10`; downstream `zip` can silently truncate ([analyze.py:27–41](</C:/code/qualiusp2026/experiments/exp14_benefit_router/analyze.py:27>)). Add exact length assertions and assert both ranking files use identical per-question paragraph counts. Also state clearly that “recall@5” means *all* supporting paragraphs appear in the top five ([analyze.py:40–41](</C:/code/qualiusp2026/experiments/exp14_benefit_router/analyze.py:40>)).
