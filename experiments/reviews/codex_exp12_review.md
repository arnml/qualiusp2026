## Null case

### 1. Matching and implementation

- **The primary changes two things at once.** It compares exp09’s conditioned, iterative M1-iter with M1-ctrl under one-shot inference ([PROTOCOL.md:45–50](</C:/code/qualiusp2026/experiments/exp12_matched_control/PROTOCOL.md:45>)). That cannot isolate the effect of query conditioning from the effect of iterative inference. **Before running:** add a matched `M1-iter` evaluation and compare both models under the same inference modes; describe the one-shot-vs-iterative contrast as a policy comparison.
- **The primary also compares training hardware.** The protocol acknowledges CPU-trained M1-iter versus GPU-trained M1-ctrl, then assumes the difference is “floating-point only” ([PROTOCOL.md:24](</C:/code/qualiusp2026/experiments/exp12_matched_control/PROTOCOL.md:24>)). The GPU M1-iter seed-0 rerun is evaluated as a replication, not used for the primary or the SVD delta ([make_notebook.py:28–37](</C:/code/qualiusp2026/experiments/exp12_matched_control/make_notebook.py:28>), [evaluate.py:55–64](</C:/code/qualiusp2026/experiments/exp12_matched_control/evaluate.py:55>)). **Before running:** use `m1_iter_s0` as the matched primary comparator and compute `D` from that same GPU run.
- **The generated notebook does not implement the registered primary decision.** Its test evaluation omits M1-iter; it neither loads M1-iter’s test orders nor calculates McNemar’s test ([make_notebook.py:35–37](</C:/code/qualiusp2026/experiments/exp12_matched_control/make_notebook.py:35>)). The protocol’s claim currently depends on an external artifact and manual analysis. **Before running:** add explicit test-order loading with ID equality checks and code for the registered paired test and CI.
- **The secondary’s registered gates are also missing from the notebook.** It selects `r*` on dev and evaluates that rank on test, but does not compute the test recovery CI or check whether `g_rand_r2` recovers less than half of `g_r2` ([make_notebook.py:38–58](</C:/code/qualiusp2026/experiments/exp12_matched_control/make_notebook.py:38>); required by [PROTOCOL.md:51–56](</C:/code/qualiusp2026/experiments/exp12_matched_control/PROTOCOL.md:51>)). **Before running:** implement both checks and save their inputs, estimates, and results.
- **Stale outputs can silently pass as current.** Training skips any existing model file, resumption accepts a checkpoint without validating its arguments, and evaluation skips any config name already in the output file ([make_notebook.py:30–33](</C:/code/qualiusp2026/experiments/exp12_matched_control/make_notebook.py:30>), [train.py:79–85](</C:/code/qualiusp2026/experiments/exp12_matched_control/train.py:79>), [evaluate.py:104–109](</C:/code/qualiusp2026/experiments/exp12_matched_control/evaluate.py:104>)). **Before running:** use a fresh run directory or validate config, commit, model hashes, and split IDs before skipping anything.
- **The notebook pulls mutable code before training.** It runs `git pull` and records the resulting commit, rather than pinning the reviewed revision ([make_notebook.py:15–17, 26](</C:/code/qualiusp2026/experiments/exp12_matched_control/make_notebook.py:15>)). **Before running:** check out a fixed commit and fail if `HEAD` differs.
- **Training pairs and shuffle appear matched for seed 0:** `ctrl` uses the same step loop, positive/negative construction, and seed-0 shuffle as `iter` ([train.py:35–45, 84–91](</C:/code/qualiusp2026/experiments/exp12_matched_control/train.py:35>); exp09 comparison [train.py:31–40, 78–85](</C:/code/qualiusp2026/experiments/exp09_iterative_rerank/train.py:31>)). But the recorded check in the protocol is not an automated assertion. **Before running:** assert pair count, labels, paragraph sequence, shuffle indices, and optimizer-step count.
- **Tokenized inputs are not length-matched.** Conditioning adds query tokens; truncation is query-only except for the fallback when a paragraph is too long ([data.py:81–91](</C:/code/qualiusp2026/experiments/exp12_matched_control/data.py:81>)). This is part of the treatment, but means different token counts and compute; the fallback can also truncate paragraph text. **Before running:** report per-arm token-length and fallback counts, or exclude/handle long paragraphs identically.
- **The dev/test source is the same underlying MuSiQue dev file**, with membership controlled by `split_ids.json` ([data.py:10–23](</C:/code/qualiusp2026/experiments/exp12_matched_control/data.py:10>)). **Before running:** assert dev300/test IDs are disjoint and match the cached exp09 ranking IDs exactly.

### 2. Statistical decision rules

- The stated McNemar power is conditional on about 90 discordant cases; after matching, the discordance rate and effect may differ. A non-significant result is not evidence of equivalence. The protocol acknowledges limited power, but should pre-register the paired effect CI and a practical-null margin ([PROTOCOL.md:45–50](</C:/code/qualiusp2026/experiments/exp12_matched_control/PROTOCOL.md:45>)).
- There are two “confirmatory” claims at α=.05 with no family-wise adjustment ([PROTOCOL.md:63](</C:/code/qualiusp2026/experiments/exp12_matched_control/PROTOCOL.md:63>)). **Before running:** use Holm across H6/H9 or explicitly label the error rates as per-claim.
- The secondary gain gate (`≥.05` on 300 dev cases) and 80% recovery threshold are noisy point-estimate cutoffs; the denominator can be small or unstable ([PROTOCOL.md:51–55](</C:/code/qualiusp2026/experiments/exp12_matched_control/PROTOCOL.md:51>)). **Before running:** define behavior for a zero/sign-changing test denominator and report the paired CI for the raw gain as well as recovery.
- Bootstrap recovery should resample question IDs jointly across `g_r*`, `ctrl_iter`, and M1-iter; ratio intervals can be unbounded or misleading when the denominator approaches zero. Specify the bootstrap method, replicate count, and handling of invalid ratios before seeing results.

### 3. What a positive result would still not establish

- It would not show that **conditioning alone** caused the gain: the primary also changes inference policy and training-query distribution. The same-inference factorial comparison above is the cheap isolating check.
- It would not show robustness to random seed: “all 3 pairs win” is descriptive, with only three GPU seeds and no uncertainty estimate ([PROTOCOL.md:25–29](</C:/code/qualiusp2026/experiments/exp12_matched_control/PROTOCOL.md:25>)). Report the paired seed differences; don’t treat three wins as a powered replication.
- A successful low-rank graft may reflect this exact base, seed, hardware, and test set; the random-rank control is only a weak comparator. Add a cheap check of `g_r2` against the GPU seed-0 delta and report per-question gains, alongside the registered random control.

**Highest priority before training:** pin code and clear/validate outputs; use GPU M1-iter seed 0 in the primary and delta; implement the registered primary test and secondary CI/control; add matched-inference comparisons.
