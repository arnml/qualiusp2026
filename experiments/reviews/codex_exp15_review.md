## Null case

**A positive result would show that these two complete retrieval policies produce different answers on this reused question set. It would not isolate whether better recall caused the difference.**

### Main confounds and code risks

- **Selection and order change together.** The primary compares two different top‑5 sets *and* their orders: [PROTOCOL.md:15–16](experiments/exp15_answer_f1/PROTOCOL.md:15), [generate_f1.py:42–45](experiments/exp15_answer_f1/generate_f1.py:42). More useful paragraphs, favorable ordering, or both could explain a gain. A fixed five-paragraph count also does not fix context tokens: paragraph lengths differ; token counts are only descriptive ([generate_f1.py:64–67](experiments/exp15_answer_f1/generate_f1.py:64)).
- **Reader sampling is uncontrolled.** The protocol specifies default sampling ([PROTOCOL.md:20](experiments/exp15_answer_f1/PROTOCOL.md:20)); the API call sets no sampling parameters ([generate_f1.py:106](experiments/exp15_answer_f1/generate_f1.py:106)). Each question gets one draw, so the bootstrap omits generation variance. Conditions run in separate blocks ([generate_f1.py:95–98](experiments/exp15_answer_f1/generate_f1.py:95)), confounding condition with time or backend changes.
- **Subset was chosen after seeing retrieval results on this set.** The ≥3-hop primary follows exp13’s explicitly exploratory, uncorrected 3/4-hop findings ([README.md:23–32](experiments/exp13_cascade/README.md:23)); the protocol acknowledges this reuse ([PROTOCOL.md:38–40](experiments/exp15_answer_f1/PROTOCOL.md:38)). Fresh F1 labels do not make the subgroup choice independent.
- **Truncation is not controlled for the reader.** The generator sends full paragraphs with no token budget ([generate_f1.py:104–106](experiments/exp15_answer_f1/generate_f1.py:104)); top‑5 token totals may differ, while `all` is much longer. Exp13’s 512-token truncation was in the ranker pipeline, not evidence that reader inputs are equal ([README.md:42–43](experiments/exp13_cascade/README.md:42).
- **Prompt and metric can shape the result.** The reader prompt is copied with a wording change ([data.py:41–60](experiments/exp15_answer_f1/data.py:41)); report the exact prompt/model settings. F1 takes the *maximum* across gold aliases ([generate_f1.py:49–50](experiments/exp15_answer_f1/generate_f1.py:49); normalization at [exp02 generate.py:50–67](experiments/exp02_cross_encoder/generate.py:50)), which is benchmark-compatible but can reward partial overlap and hide answer-format errors. Include EM and inspect disagreement examples.
- **Index decoding looks plausible, but is brittle.** It decodes positional 5-character chunks as `ord(ch)-97` ([generate_f1.py:40–45](experiments/exp15_answer_f1/generate_f1.py:40)); the artifact note says it is in `split_ids.json` order. No runtime checks enforce length, range, or ID alignment. `load` uses that split order ([data.py:20–23](experiments/exp15_answer_f1/data.py:20)).
- **Resumption/reporting can accept contaminated records.** `done` trusts any recorded ID ([generate_f1.py:97–98](experiments/exp15_answer_f1/generate_f1.py:97)); report collapses duplicate IDs into a dict and checks only the final ID set ([generate_f1.py:62–64](experiments/exp15_answer_f1/generate_f1.py:62)). It does not verify each record’s condition or paragraphs. A blank model response is recorded as an answer, not a missing call ([generate_f1.py:108–110](experiments/exp15_answer_f1/generate_f1.py:108)). Failures do remain retryable.

### Statistical limits and alternatives

- **Power is weak for a small answer-quality effect.** The protocol estimates roughly 50% power ([PROTOCOL.md:26–28](experiments/exp15_answer_f1/PROTOCOL.md:26)); a nonsignificant result would be inconclusive, and a barely positive lower bound could reflect a small, unstable effect.
- The paired percentile bootstrap is reasonable for question-level differences ([generate_f1.py:53–55](experiments/exp15_answer_f1/generate_f1.py:53)), but resamples questions only—not reader draws. It also does not preserve hop strata. The one-sided 5th percentile for non-inferiority is consistent with its stated rule ([generate_f1.py:73–75](experiments/exp15_answer_f1/generate_f1.py:73)).
- The protocol has one named primary, so no correction is needed if that alone supports the claim. But all-question positivity, 2-hop non-inferiority, and hopwise descriptive results invite selective secondary claims ([PROTOCOL.md:29–34](experiments/exp15_answer_f1/PROTOCOL.md:29)); explicitly label them exploratory and avoid treating them as confirmation.
- A positive result would still be compatible with **ordering effects, longer/more useful selected text, stochastic reader luck, or a selected subgroup**. Cheap checks: reorder the same five passages consistently; compare a shared-original-order analysis; report per-condition context-token distributions and truncation/failure rates; rerun a paired subset with repeated reader calls; inspect errors by hop and whether missing gold passages correspond to F1 drops.

### Changes before the run, ranked

1. **Fix the estimand:** add a shared-order top‑5 comparison (same five passages ordered by dataset index, or a prespecified common rule) alongside native order; label native-order result as policy effect, not recall effect.
2. **Control reader variance and drift:** set and record explicit sampling settings; randomize/interleave conditions per question; repeat calls on a prespecified subset (ideally all primary cases) and include call-level variance. Record exact model identifier and full prompt.
3. **Repair integrity checks:** assert encoded string length is `5 * len(rows)`, decoded indices are in range, and top‑5 artifact IDs/order match `rows`; on report reject duplicate IDs, wrong `condition`, unexpected paragraph lists, blanks, and missing IDs.
4. **Treat token budget as a design variable:** report context-only and full-prompt token distributions by condition/hop; add a prespecified token-matched comparison or truncate all contexts to the same documented budget. Report any rejected/failed requests.
5. **Reframe inference:** call ≥3-hop analysis exploratory on this dataset, or validate it on a new untouched set. Keep one primary claim; mark all subgroup/secondary findings descriptive. Add repeated-reader uncertainty before interpreting a narrow CI as evidence.
