# exp12 protocol: pair-matched one-shot control for the iterative ranker (pre-registered 2026-11-15)

## Why

All three reviews (`../reviews/SYNTHESIS.md`) flag the same confound in exp09 and exp11:
- M1-iter was trained on **18,101 pairs (1,132 steps)**, M1 on **8,338 (522 steps)**. The questions were the same.
- So "iteration wins" (exp09, H6) and "the iteration change is rank 2" (exp11, H9) may partly be "more training".

## Question

1. **Primary (H6, de-confounded):** with **identical training pairs, labels, order, steps and schedule**, does conditioning the query on the already-picked paragraphs still beat one-shot scoring?
2. **Secondary (H9, de-confounded):** is the change that adds *only* query conditioning, D = M1-iter − M1-ctrl, still low-rank?

## The control model: M1-ctrl

- `train.py --mode ctrl` builds **M1-iter's exact example list**: the same questions (exp09's seeded 1,000), the same positives per step (the remaining gold), the same negative draws (seeded per question and step), the same shuffle, batch 16, lr 2e-5, 1 epoch, max length 512, seed 0, initialised from A1.
- **The only change: the query is the question alone,** with no " [SEP] " prefix of picked paragraphs.
- This was checked in code before registration: same length, identical (paragraph, label) sequence, and only the query strings differ.
- The resulting model has seen exactly what M1-iter saw, minus the conditioning. The positive mix also matches: later-hop gold is over-represented, as in M1-iter.
- **Not retrained:** M1 and M1-iter, frozen from exp09. M1-iter's rankings come from exp09 (identical to a re-run, exp10 check).

## Hardware and replication (decided before any training)

- **Hardware:** all exp12 training and inference run on a **Colab T4 GPU** (`exp12_colab.ipynb`, generated by `make_notebook.py`). Inputs are staged on Google Drive. M1-iter (exp09) was trained on CPU, so the primary compares a CPU-trained M1-iter with a GPU-trained M1-ctrl. The difference is floating-point only: the code, seed, pairs and order are the same.
- **Hardware-matched replication (descriptive, the replication gate):**
  - M1-iter is retrained on GPU with seed 0 (`m1_iter_s0`).
  - Seeds 1 and 2 of both models are trained (`m1_ctrl_s{1,2}`, `m1_iter_s{1,2}`). The seed changes the shuffle and dropout; the pairs are unchanged.
  - Reported: recall@5 of each seed pair (iterative vs one-shot) on test, the mean difference and its spread across seeds.
  - **"Replicates"** = M1-iter > M1-ctrl in all 3 GPU seed pairs.

## Evaluation (`evaluate.py`)

| Config | Model | Inference |
|---|---|---|
| `ctrl_oneshot` | M1-ctrl | one-shot |
| `ctrl_iter` | M1-ctrl | iterative (exp09: 4 greedy steps) |
| `g_r{1,2,4,8}` | M1-ctrl + rank-r SVD of D (exp06/exp11 method) | iterative |
| `g_rand_r2` | M1-ctrl + norm-matched random rank 2 (seed 0) | iterative |
| M1-iter (exp09 file) | M1-iter | iterative |

**Metric:** full recall@5 (exp09's primary). Orders are stored, so recall@k is reported for k = 2 … 15.

## Pre-registered tests

1. **Primary (test, 400):** recall@5 of **`iter_iter`** (M1-iter retrained on GPU, seed 0, iterative inference) vs **`ctrl_oneshot`** (M1-ctrl seed 0, one-shot), McNemar exact, two-sided α = 0.05. This is a **system comparison**: each model in the inference it was trained for. The 2×2 below separates model from inference.
   - **Success** = M1-iter higher and p < 0.05.
   - **Power:** exp09's comparable pair had 93 discordant questions. With about 90, the minimum detectable effect at 80% power is about **+0.07 recall@5**, and an effect around 0.05 has roughly 50% power. A null result therefore does not show "no effect" below about 0.07. In that case the CI is reported.
   - Reading the result:
     - **Success:** H6 survives the confound.
     - **Fail with M1-ctrl ≥ M1-iter:** the exp09 gain was more training, not iteration.
2. **Secondary (dev300 → test):** gain gate: if recall@5(M1-iter) − recall@5(`ctrl_iter`) on dev300 is below 0.05, the secondary is **not testable**.
   - Otherwise: r* = the smallest rank in {1, 2, 4, 8} with **≥ 80%** recovery on dev300. Recovery = (R(g) − R(ctrl_iter)) / (R(M1-iter) − R(ctrl_iter)).
   - **Holds if both:**
     - r* ≤ 8
     - on test, the 95% paired-bootstrap CI of recovery for r* has a lower bound > 0.5 (the numerator and denominator are resampled together)
   - **Control:** `g_rand_r2` must recover less than half of `g_r2`.
3. **Descriptive:**
   - `ctrl_iter` vs `ctrl_oneshot`: does M1-ctrl benefit from iterative inference without being trained for it?
   - M1-ctrl vs M1 (one-shot): what do 2.2× more pairs buy?
   - recall@k curves, by hops
   - **Geometry, no inference:** singular-value spectra and stable rank of D, of exp11's D_it = M1-iter − M1, and of D_more = M1-ctrl − M1. Principal angles between the top-2 subspaces of D and D_it, per matrix, against a random-subspace baseline.

**Claim ledger:** the primary is confirmatory for H6. The secondary is confirmatory for H9 (de-confounded version). Everything else is exploratory.

## Budget

- **On the T4:** about 10–20 min per training run, and minutes per evaluation config.
- **If Colab cuts the session:** the notebook resumes from checkpoints on Drive.
- **If GPU access is lost for more than a day:** the primary (M1-ctrl seed 0) runs on CPU instead. Seed replicates are dropped and recorded in `results/budget.json`.

## Honest priors

- **Primary likely holds, but smaller.** exp09's +0.068 included the pair-count advantage; the de-confounded gain may fall near the minimum detectable effect.
- **Secondary uncertain.** D may be even lower-rank, since D_it also contained "more training". Or the conditioning change may need more rank once the shared "more data" direction is removed.
- **Seeds:** the primary uses one seed; the GPU seed replicates (above) address this descriptively.

## Changes after the adversarial pre-run review (Codex, `../reviews/codex_exp12_review.md`; before any training)

1. **Primary and D use the hardware-matched GPU M1-iter (`m1_iter_s0`), not exp09's CPU model.** The CPU model is compared descriptively, including GPU vs CPU M1-iter.
2. **2×2 (descriptive):** each of M1-iter and M1-ctrl is run with both one-shot and iterative inference (`iter_iter`, `iter_oneshot`, `ctrl_iter`, `ctrl_oneshot`). This separates "trained with conditioning" from "inferred iteratively".
3. **The analysis is code, written before training** (`analyze.py`):
   - McNemar plus a paired-bootstrap CI of the difference
   - recovery: 5,000 joint resamples of question IDs, and a resample whose denominator is ≤ 0 counts as recovery 0
   - the test gain and its CI, reported next to recovery
   - the random control
   - seed differences, with their mean and SD
4. **Pinned code:** the notebook checks out the registration commit and writes to a fresh Drive folder named by that commit.
5. **Assertions:** ctrl pairs equal iter pairs (train.py), the splits are disjoint, and evaluation IDs equal the split IDs.
6. **Error rates are per claim** (H6 primary, H9 secondary), with no family-wise correction. Three seeds are descriptive, not a powered replication.
